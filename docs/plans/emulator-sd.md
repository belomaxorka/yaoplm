# План: SD эмулятора карты памяти (sd2psx / sd2psXtd) в YAOPLM

Источник — сессии 2026-10-26 с владельцем продукта:
- прошивка PSXMemCard Gen2 обновлена до sd2psXtd 1.4.0;
- заводская microSD описана и сохранена, раскладка перенесена на Kingston 128 ГБ;
- после PR #53 владелец оставил только работу через картридер, а заводскую карту сделал тестовой;
- на вопросы плана владелец ответил в тот же день.

Решения записаны в **ADR-0048**. Факты лежат в трёх местах:
- research/19 — устройство владельца, его SD, загрузочные карты, переезд, что нужно YAOPLM;
- research/07 §1.4 и §2.7 — форк OPL с MMCE, раскладка SD у sd2psx, карты по ID игры;
- research/06 §1.4 — таблица разделов.

Требования SPEC: DEV-2 (распознавание носителя), DEV-3 (здесь — защита от форматирования), DEV-4 (управление картами и новая SD), LIB-1 (профиль), LDR-1/LDR-3 (форк с MMCE), LDR-5 (OPL внутри загрузочной карты), VMC-2 (сейвы).

## Что решил владелец (2026-10-26)

- **Только картридер.** microSD эмулятора вставлена в картридер ПК — так YAOPLM с ней и работает.
  - Кода для USB и последовательного порта эмулятора нет: по USB прошивки не дают доступа к файлам SD (раздел «Почему без USB»).
  - Прошивку эмулятора YAOPLM не обновляет: хватает перетаскивания UF2 по README sd2psXtd.
- **SD эмулятора — отдельный вид носителя.** Программа её распознаёт и никогда не портит:
  - не пишет в `.sd2psx/` и `MemoryCards/` иначе как через явные функции работы с картами;
  - не ставит туда загрузчик — ни в корень, ни куда-либо;
  - не даёт её форматировать.

  Потерять загрузочные карты с FreeMcBoot дорого.
- **OPL обновляется внутри загрузочной карты** (LDR-5), сейвы редактируются в образах карт (VMC-2).
- **Игры для OPL с MMCE** — в обычной раскладке OPL (`CD/`, `DVD/`, `ART/`, `CFG/`, `VMC/`…) в корне SD.
- **Новая SD без исходной** собирается из образов SD Builder (последний PR). Своя раскладка восстанавливается из копии.
- **Проверки на консоли** пока откладываются: консоли нет. Каждый PR кладёт свой чек-лист файлом в `docs/testing/` (по-русски) и строкой в `docs/testing/README.md`.

## Решено (ответы владельца 2026-10-26, все рекомендации приняты)

1. **Веха.** Распознавание и защита (PR 1) — в M5, до форматтера DEV-3. PR 2–6 — в M6 (v0.3.0), рядом с «играми на SD эмулятора карты памяти» и форками с MMCE. Этапы LDR-5 и VMC-2 в SPEC — v0.3.
2. **Режим.** Третий режим подключения — «В эмулятор карты памяти», рядом с «Вставляется в консоль» и «По сети (SMB)» (ADR-0047).
   - Определяется по признакам эмулятора на SD, а не по месту.
   - Защита привязана к признакам, а не к режиму: смена режима её не снимает.
   - Пустую SD можно перевести в этот режим вручную.
   - Выбора «это не SD эмулятора» нет.
3. **Версия OPL.** Вопрос строкой задаётся и на SD без папок OPL. В нём только сборки с MMCE: форк OPL с MMCE, YAOPL, RiptOPL, wOPL и «Не знаю».
   - «Не знаю» даёт правила форка с MMCE (то есть 1.2.0 beta).
   - «Создать папки OPL» появляется после ответа.
   - С PR 2 ответ берётся из версий OPL внутри загрузочных карт.
   - YAOPL считается сборкой с MMCE; перед PR это перепроверяется по текущему коду YAOPL (research/16 §13).
4. **LDR-5.** Форк ps2-mmce (`OPL-MMCE-beta-2`) входит в каталог в PR 3 с хешем, закреплённым после одной загрузки (`digest` у релиза нет). В загрузочную карту ставится одиночный ELF: форк с MMCE, YAOPL или OPL 1.2.0 beta (с предупреждением «игр с SD не увидит»). RiptOPL и NHDDL — нет.
5. **Резервные копии.**
   - Перед каждой записью внутрь `.mcd` — копия всего образа в `.yaoplm/backup/` на той же SD.
   - «Копия SD на компьютер» (`.sd2psx/` и `MemoryCards/` с описью SHA-256) — кнопкой на карточке и галочкой в плане записи в `MemoryCards/`, пока у этой SD нет копии. Галочка включена по умолчанию, но не обязательна.
6. **Доктор.**
   - GPT или SD без таблицы разделов — ошибка для 1.4.0; станет предупреждением, когда выйдет релиз с GPT.
   - `CardSize` больше 8 — предупреждение.
   - Файлы `.crp.<n>` — предупреждение со списком.

**Пожелания владельца для PR 3 и PR 4** (2026-10-26, после слияния PR #54; решить в этих PR, при изменении ADR-0048 — новым ADR):
- MMCE — про то, откуда OPL читает игры, а не где лежит ELF. Поэтому сборки с MMCE (форк, YAOPL, RiptOPL) предлагать и при установке на флешку: с эмулятором в консоли они увидят игры на его SD.
- В загрузочную карту — больше сборок на выбор: OPL 1.1.0 (с предупреждениями: только FAT32, без ZSO и MMCE), RiptOPL — если пакет поместится в карту (проверить размер и место).
- Юбилейная сборка (`OPNPS2LD10th.ELF` на заводской карте): выяснить происхождение. В каталог — только при официальном релизе (ADR-0014).
- Старые беты upstream на GitHub не хранятся (research/07 §1.11): их предложить нельзя.

Агент решил сам, владелец согласился:
- MemCard PRO 2 — только признаки и защита. Признаки исходной sd2psx проверены по её коду: `MemoryCards/PS2|PS1/…` без `.sd2psx/`. PicoMemcard+ — когда появится клон.
- Признаки ищутся в открытой папке и в папках над ней до корня тома: папка внутри SD защищена так же, а копия SD в папке на компьютере тоже узнаётся.
- Простой режим: строка «SD эмулятора карты памяти», каналы с именами и предупреждения видны в обоих режимах; `settings.ini`, список карт и `.crp` — в расширенном.
- `.yaoplm/` (журнал, резервные копии) в корне SD разрешена.
- Один модуль файловой системы карты для `VMC/*.bin` OPL и `.mcd` эмулятора.

## Почему без USB (справка)

Файлов по USB нет ни в одной прошивке, поэтому YAOPLM USB не использует (ADR-0048, «Отвергнуто»).

| Прошивка | Что видно по USB | Что можно |
|---|---|---|
| до 1.4.0 | ничего (только питание) | — |
| **1.4.0** (у владельца) | последовательный порт (USB CDC) и интерфейс сброса, VID `2E8A` PID `000A`. Появляется только после того, как SD смонтирована | `help`, `reset bl`, `reset dev`, `channel up/down`, `set channel <n>`, `card up/down`, `set card <n> [channel <n>]`, `set game <id> [channel <n>]`, `set mode ps1/ps2`, `set variant retail/proto/conquest/arcade` |
| ветка `develop` (b3c9a54, не выпущена) | то же | ещё `version` и **только чтение** SD: `ls [путь]`, `stat <путь>`; пока PS2 работает с картой — `Busy: card operation in progress` (PR #106) |

- **Режима флешки (USB mass storage) нет** ни в sd2psXtd, ни в исходном sd2psx: включён только `pico_enable_stdio_usb`. Чтения и записи файлов по порту нет ни в одной ветке, запросов на это в трекере тоже нет.
- **Запись по USB** была бы доработкой прошивки upstream (GPL-3). Ограничения: USB full speed, порядка 1 МБ/с, так что игра на 4 ГиБ шла бы больше часа; писать, пока консоль работает с картой, нельзя.
- **Порт не узнать по VID/PID:** `2E8A:000A` — стандартный для любой платы на RP2040 со stdio по USB.
- Стенограмма `help` с устройства владельца и протокол порта (DTR, эхо, приглашение `> `) — в истории этого файла (PR #53) и в research/19 §1.

Поэтому OPL обновляется внутри образа, по пути из меню: YAOPLM читает `SYS-CONF/FREEMCB.CNF` или `PS2BBL.INI` в той же карте и показывает, какой пункт какой ELF запускает (на заводском канале 1 пункт 4 «Open PS2 Loader (MMCE Beta2)» запускает `mc?:/APPS/OPL-MMCE-BETA2.ELF`). Сами конфиги лаунчеров не правятся (BOOT-1).
  - **Меняется ровно один файл** (вопрос владельца 2026-10-26). Карта не распаковывается и не собирается заново: заменяется только выбранный ELF, то есть его кластеры, цепочка FAT и запись каталога. ELF находится по версии внутри, а не по имени (имена бывают перепутаны, research/19 §4).
  - Новый образ собирается во временном файле. Перед заменой все остальные файлы и папки сверяются побайтно со старым образом, кроме заменённого ELF и `OPL/conf_opl.cfg`. Любое отличие отменяет запись.
  - Нехватка места внутри карты — ошибка плана с числом КБ; освобождённые кластеры заменяемого ELF засчитываются. Место считается так, как его считает консоль: кластеры только ниже 8001 на карте 8 МБ, остальное — запас драйвера (research/20 §4.3). В канале 1 заводской SD так свободно 465 КБ, а ELF около 1,3 МБ: новый ELF до ~1,74 МБ встаёт на место `OPL-MMCE-BETA2.ELF`, лишним файлом — нет.
  - **Правила записи в образ — research/20 §3** (разбор исходников FreeMcBoot, PS2BBL, OPL, драйвера карты ps2sdk и прошивки sd2psXtd по просьбе владельца 2026-10-26). Главное:
    - отказ, если резервный блок 2 не стёрт (консоль не закончила запись), если в карте есть общие кластеры, петли или кластеры за пределом консоли, если это мультиустановка FreeMcBoot (`SYS-CONF/FMCBUINST.dat`, `SYS-CONF/uninstall.dat`, записи с режимом `0x8415`);
    - пишется только ELF, который YAOPLM узнал как OPL: лаунчеры проверяют лишь, что файл открывается, и битый ELF вешает консоль;
    - кластеры выделяются, как у консоли (сначала свои, потом самые младшие свободные), режим, `attr` и время создания записи сохраняются, суперблок и резервные блоки не трогаются;
    - новый образ пишется рядом, в `MemoryCards/PS2/BOOT/`, под именем не `.mcd` и переименовывается поверх старого: без мгновения, когда файла нет (иначе прошивка создаст пустую карту), и без временных папок в `MemoryCards/PS2/` (каждая папка там — карта).
  - **Что может перекрыть меню карты** (research/20 §1.1): `FREEMCB.CNF` и `UPDT/OPL.ELF` на флешке у FreeMcBoot; у PS2BBL — `mmce?:/APPS/OPNPS2LD.ELF`, `mmce?:/APPS/OPL-MMCE.ELF` и `mmce?:/PS2BBL/PS2BBL.INI` в корне SD, а ini самой карты он читает последним. То, что видно на SD, YAOPLM показывает рядом со списком пунктов; флешку называет чек-лист.
- [ ] **PR 5 — сейвы (VMC-2), M6.**
  - **Системное в загрузочной карте неприкосновенно** (вопрос владельца 2026-10-26). Функции сейвов не удаляют и не заменяют:

## Тестовые данные и устройства

- **Тестовая карта — заводская microSD 8 ГБ** (серийный номер тома `C0EE-DE33`, MBR, exFAT). Буква любая: узнавать по серийному номеру (`. scripts/testdata.ps1`).
  - Сначала только чтение. Запись — только планами YAOPLM и после подтверждения владельца.
  - Полная проверенная копия: `$YAOPLM_TESTDATA\backups\psxmemcard-gen2-sd-2026-10-26\files`, опись с SHA-256 — `files.tsv` рядом.
  - После тестов вернуть карту в заводское состояние из копии, сверить хеши по `files.tsv` и описать, что на ней лежит.
- **Kingston 128 ГБ** (`0008-0E00`) — рабочая карта владельца. Не используется и не вставляется.
- Тестовая флешка `3C76-1797` к этой задаче не относится.
- Настоящие образы FreeMcBoot — в репозиторий никогда. Тесты на реальных данных — `#[ignore]` с `YAOPLM_TESTDATA`; фикстуры — синтетические (`yaoplm-test-support`).
- **Клоны в `refs/`** (`git -C <dir> pull`):
