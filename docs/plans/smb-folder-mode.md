## Что решил владелец

1. **Режим — по месту папки** (2026-10-25). Флешка, SD-карта и USB-диск — носитель для PS2. Папка на внутреннем диске, сетевая папка и корень сервера — папка для SMB: в PS2 её не вставить. На карточке переключатель для исключений, выбор запоминается для носителя.
2. **Пустая папка для SMB** — «Создать папки OPL» и вопрос «Какой OPL на консоли?» с ответом «Не знаю». Загрузчик не ставится: OPL запускается с карты памяти (FMCB) или флешки.
3. **Открыт целиком системный диск** — предупреждение, что для раздачи лучше отдельная папка, и предложение создать, например, `C:\PS2`. Запись в корень не запрещается: она и так идёт только внутри выбранной папки.
4. Раньше в тот же день: в режиме SMB надписи «Не подходит для OPL» быть не должно, а вопрос о версии нужен, чтобы файлы, которые YAOPLM пишет в папку, подходили к OPL на консоли.

## Как сейчас (на `main` после PR #40)

## Что OPL делает с папкой по SMB (коротко; подробно — research/18)

- SMBv1 (`NT LM 0.12`) у upstream, YAOPL, wOPL и форка с MMCE. RiptOPL C (`main`) умеет ещё SMB2/SMB3 по настройке `smb_dialect`, порт по умолчанию 1111; C++-версия RiptOPL пока только SMBv1.
- При подключении OPL сам создаёт на шаре `CFG THM LNG ART VMC CHT APPS CD DVD` (тот же набор, что LIB-3) и пишет `CD/games.bin`, `DVD/games.bin`, если шара доступна на запись. VMC, CFG, CHT и обложки — тоже на шаре; сохранения в VMC требуют записи.
- Настройки OPL (`conf_*.cfg`) на шару никогда не пишутся (только карта памяти, BDM, HDD), загрузчик на шаре — лишь копия. Единственный признак версии в папке для SMB — размер записи `games.bin`.
- ISO и ZSO (ZSO не читает 1.1.0). Смещения 64-битные: игра больше 4 ГиБ — один ISO, если его держит ФС папки на компьютере; `ul` — не больше 10 частей. Имя образа до 159 байт (уже соблюдается, IMP-4). Списка кластеров нет — правило фрагментов (IMP-7b) не действует.
- `eth_prefix` (подпапка на шаре) — до 33 байт; важно для NET-2 позже.

## Задачи

### 1. Режим носителя в ядре (`yaoplm-device`)
- Перечисление режима (рабочие имена `Ps2Device`, `SmbFolder`) и правило по умолчанию: `volume.is_external()` → носитель для PS2, иначе папка для SMB (внутренний диск, `Remote`, `Unknown`, корни сервера и Docker). Причина — фраза: «съёмный носитель», «папка на диске компьютера», «сетевая папка», «папка сервера».
- `DiagnoseOptions` получает режим. В режиме SMB:
  - нет `SystemVolume`, `FsUnreadable`, `ExfatNeedsOpl12`, `FatNeededToBoot`, `ExfatRecommended`, `SectorSize`, кластеров, `GptUnsupported`, `NoPartitionTable`, `Misaligned`, `NotExternal`;
  - остаются `ReadOnly` (ошибка: YAOPLM не сможет писать), `AppleDouble`;
  - `LargeGamesAsUl` — только если ФС папки FAT32/FAT16;
  - правила SMB для любой папки этого режима, не только `Remote`: текст `RemoteShare` переписать под режим, у RiptOPL — с SMB2 (`smb_dialect`); новый код или тот же — реши сам, но коды стабильны для переводов;
  - открыт корень системного тома (`root` совпадает с `volume.root` и `volume.system`) — предупреждение «Для раздачи лучше отдельная папка» (новый код).
- В режиме PS2 всё как сейчас.
- Юнит-тесты в `advice.rs`: системная папка в режиме SMB без ошибок; FAT32 на компьютере → `ul`; RiptOPL → упоминание SMB2; корень системного диска → предупреждение; только чтение → ошибка; режим PS2 не изменился.

### 2. Профиль, вопрос и фрагменты
- Определение профиля (`detect.rs`) не меняется: в папке для SMB работают те же уровни, обычно решает `games.bin` или ничего.
- Когда спрашивать о версии, лучше считать в ядре и отдавать полем (как шаг UI-6, SPEC §5.11.2: «шаг вычисляет ядро»): профиль по умолчанию, носитель пригоден и (`library` или режим SMB). Тогда CLI и веб говорят одно.
- Предупреждения о фрагментах (IMP-7b) в режиме SMB не выдаются — ни в сканировании, ни после записи. Режим доходит до `ScanLibrary` и планов так же, как профиль.

### 3. API и CLI
- `DeviceInfo.mode`: режим, источник (`detected` или `override`) и причина-фраза. Параметр запросов с переопределениями режима по ключу носителя — по образцу `overrides` профиля — у `ListDevices`, `InspectDevice`, `ScanLibrary` и запросов планов, где важны фрагменты. После слияния #39 (он тоже правит `protocol.rs`).
- `cargo test -p yaoplm-api --features ts-export` — новые типы в `web/src/api/generated/`.
- CLI: `yaoplm devices` и `yaoplm device <root>` показывают режим и причину; `--mode auto|ps2|smb` у `device` и `scan` (по умолчанию `auto`). Обновить раздел «Commands» в CLAUDE.md.

### 4. Веб
- Настройки: `modeOverrides` по тому же ключу носителя, что `profileOverrides`; чтение старых настроек без поля.
- Карточка носителя и шапка библиотеки: строка режима («Консоль читает: вставленным в PS2» / «по сети (SMB)», причина, «Изменить», «Вернуть «Авто»»). В простом режиме — решить по SPEC §5.11.1, где ей место; режим должен быть виден там, где виден вопрос о версии.
- Вопрос о версии — по новому полю из ядра (п. 2).
- Пустая папка для SMB: главная кнопка «Создать папки OPL» (`PlanInit`, обычный план с подтверждением) и вопрос о версии. Кнопок установки загрузчика, форматирования и «Подготовить носитель…» у папки для SMB нет.
- Корень системного диска: предупреждение и «Создать папку…» — план, который создаёт подпапку внутри корня, и после записи открывает её как библиотеку. На сервере корни задаёт администратор: там только предупреждение.
- Тексты по глоссарию `docs/I18N.md` (носитель, папка, флешка), en и ru в одном коммите.

## Решить по ходу (записать в ADR-0044)
- ELF загрузчика в папке для SMB — копия, а не то, что запускает консоль. Предложение: уровни определения оставить, а в причине профиля писать, что файл лежит в папке. Если решишь понижать уверенность — спроси владельца.
- Корни сервера: по общему правилу (в Docker шина не видна → папка для SMB; флешка, вставленная в сам сервер на Linux, → носитель для PS2) или всегда SMB. Предложение: общее правило плюс переключатель.
- Внутренний диск, который владелец вставляет в PS2 через USB-адаптер, ОС видит как USB-диск, то есть носитель для PS2 — правило не ломается; проверить на `windows-sys` и Linux, что шина USB определяется.
- Названия режимов в интерфейсе: «Носитель для PS2» / «Папка для SMB» или «вставляется в PS2» / «по сети» — по глоссарию.

## Проверка на PS2 (для PR)
1. Папка на диске компьютера раздана по SMBv1 (на Windows — «Общий доступ» и компонент «SMB 1.0/CIFS Server» или лаунчер PS2-Servers), OPL 1.2.0 beta или YAOPL с FMCB: игры, добавленные YAOPLM, видны и запускаются; ISO больше 4 ГиБ одним файлом; ZSO.
2. После первого просмотра на консоли в папке появились `CD/games.bin`, `DVD/games.bin`, и карточка YAOPLM говорит «OPL 1.2.0 beta: по games.bin» без вопроса.
3. VMC в папке для SMB: сейв создаётся и читается.
4. OPL 1.1.0 по SMB с ответом «OPL 1.1.0» (или «Не знаю»): YAOPLM не предлагает ZSO, игры видны.
5. RiptOPL по SMB, если есть возможность, — с SMBv1 и с SMB2.
6. Пустая папка: «Создать папки OPL» → OPL видит папку без ошибок.
