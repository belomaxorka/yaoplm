# M5: ближайшие небольшие PR без новых решений (план от 2026-10-27)

Решение владельца продукта 2026-10-27: после плана доводки (`m5-ui-polish.md`) идут эти PR, в этом порядке, каждый отдельной веткой `m5/<тема>` от `main`. Решения по ним уже приняты (пункты ROADMAP M5 от 2026-10-24 и 2026-10-26), ADR не нужны. Правила те же, что у прохода v0.2.0: `release-ui-consistency.md`, `release-0.2.0-ui-findings.md` §7, `docs/I18N.md` «Для кого тексты»; тест красный → зелёный; e2e по затронутым спекам дважды (файлами, не `--grep`); release-pass на четырёх прогонах (из `web/`, не параллельно с e2e); скриншоты en/ru × светлая/тёмная в `pr-assets` (`release-0.2.0/pr-<тема>/`); описание PR с таблицей «тест → на main → сейчас» и строка в `docs/testing/README.md`. Машина общая: чужие процессы не трогать, свои серверы гасить через `preview_stop`.

## PR 1. Оболочка десктопа: без меню WebView2 и без выделения интерфейса (`m5/desktop-chrome`, UI-5)

**Сейчас.** Правый клик в любом месте окна десктопа открывает меню WebView2 («Назад», «Обновить», «Сохранить как», «Печать», «Другие инструменты»); курсором выделяется всё подряд, как на веб-странице. В `apps/desktop/src-tauri/src/lib.rs` и `tauri.conf.json` ни меню, ни выделение не настраиваются; в `web/src/index.css` нет `user-select`.

**Нужно.**
- Меню WebView2 в десктопе не открывается нигде, кроме редактируемых полей (`input`, `textarea`, `contenteditable`), где нужны «Вырезать», «Копировать», «Вставить». В браузере (`yaoplm-server`) родное меню остаётся. Своих меню по правому клику не добавлять: решение владельца 2026-10-27 — единственный полезный пункт, «Обновить», и так есть на панели библиотеки и на экране носителей.
- Выделение текста в десктопе выключено у элементов интерфейса (подписи, кнопки, карточки, меню, заголовки) и оставлено там, где текст копируют: пути, ID, названия игр, строки для лаунчера (FMCB, PS2BBL), сообщения об ошибках (`role="alert"`), журнал задания, ключи CFG, серийный номер носителя.
- Реализация в веб-слое, одна для обоих мест: `main.tsx` ставит `data-desktop` на `<html>`, когда `isTauri()`; обработчик `contextmenu` на `document` с `preventDefault`, кроме редактируемых полей; в `index.css` под `html[data-desktop]` — `user-select: none` для `body` и `user-select: text` для класса `selectable` (или `data-selectable`), который получают перечисленные элементы. Через Tauri это тоже можно (`WebviewWindowBuilder::initialization_script`), но тогда десктоп и сервер расходятся.

**Тесты.** Юнит: с подменённым `isTauri` — у `<html>` есть `data-desktop`, событие `contextmenu` на кнопке отменено, на `input` — нет; без Tauri — ничего из этого. Класс `selectable` стоит у пути и ID на карточке игры, у строк лаунчера в `install-6-boot-hints`, у ошибки сканирования. CSS проверить в самом десктопе через `web/tests/release/desktop.mjs` (CDP 9222): `getComputedStyle(...).userSelect` у заголовка карточки `none`, у пути `text`; правый клик по карточке не открывает меню (скриншот). Release-pass в браузере не меняется.

## PR 2. Панель инструментов библиотеки (`m5/library-toolbar`, LIB-5, UI-5; находка 2.5 и п. 11 обхода)

**Сейчас.** `web/src/features/library/LibraryPage.tsx`: два ряда переключателей «Все / CD / DVD» и «Все / ISO / ZSO / UL», две кнопки-счётчика «С предупреждениями» и «Без обложки», селектор поля сортировки (`filters.ts`: `title`, `startup`, `size`, `media`, `format`) и отдельная кнопка направления, две кнопки «Скачать картинки» и «Импортировать картинки» (вторая — в меню «Ещё»). Заголовки столбцов в виде списком не сортируют; после удаления игры сортировка сбрасывается (п. 11 `m5-walkthrough-findings.md`).

**Нужно.**
- Один селектор сортировки с направлением внутри: «Название А→Я», «Название Я→А», «ID». Размер, тип диска и формат из сортировки убрать (`sortKeys`, `effectiveFilters`, параметры URL); сохранённое значение старого ключа читать как «Название А→Я».
- Фильтры одним меню «Фильтр» с флажками: тип диска (CD, DVD), формат (ISO, ZSO, UL), «с предупреждениями», «без обложки»; на кнопке — число включённых фильтров. Простой режим по-прежнему без счётчиков и сортировки (UI-4, `effectiveFilters`).
- Одна кнопка «Картинки…» вместо «Скачать картинки» и «Импортировать картинки»: окно с двумя путями — «Из источников» (нынешний `ArtFetchDialog`) и «Из своего набора» (нынешний `ArtImportDialog`). В простом режиме — сразу «Из источников», как сейчас.
- «Проверить дампы» и «Конвертировать…» остаются в «Ещё» до массовых действий (LIB-7).
- Заголовки столбцов в виде списком сортируют (щелчок — поле, второй — направление); сортировка и фильтры переживают удаление игры и возврат из карточки.
- Та же лексика во всех местах («Картинки…» — и на карточке игры, PR 3).

**Тесты.** `LibraryPage.test.tsx`: варианты сортировки, старый ключ `size` в хранилище → «Название А→Я», меню «Фильтр» со счётчиком, одна кнопка «Картинки…» и её два пути, сортировка по заголовку столбца; `simpleMode.test.tsx`: в простом режиме нет сортировки и счётчиков. E2E: `library.spec.ts`, `art.spec.ts`, `simple-mode.spec.ts`, `walkthrough.spec.ts`. Release-pass: `library*`, `art-import`, `art-fetch`.

## PR 3. Одно окно картинки на слот (`m5/art-one-window`, ART-2, ART-3; находка 2.6)

**Сейчас.** `web/src/features/art/ArtSlots.tsx`: у каждого из восьми слотов две кнопки — «Скачать» (`art-download-<kind>`, открывает `ArtVariantsDialog` с заданием `FindArt`) и «Заменить» (`art-replace-<kind>`, меню «Из файла…» / «Из папки сервера» / «Из буфера обмена»), плюс «Удалить». «Скачать» как слово неверно: ничего не скачивается на компьютер, выбирается картинка для носителя. Поиск вариантов — задание (`fetchArt`), и оно показывается на странице заданий и в плавающей панели.

**Нужно.**
- У слота одна кнопка «Выбрать…» и «Удалить». «Выбрать…» открывает одно окно: сверху варианты из источников (как сейчас в `ArtVariantsDialog`, с поиском при открытии), ниже «Из файла…» (десктоп) или «Из папки сервера», «Из буфера обмена». Выбор любого пути ведёт к тому же плану записи, что и сейчас.
- Поиск вариантов для одного слота — не задание для пользователя: его нет на странице заданий и в панели, как у сканирования библиотеки (`noLog` и фильтр по виду в `JobsPage.tsx` и панели; сам `FindArt` в ядре можно оставить заданием, если отменять его по закрытию окна, как сейчас). Запись картинки остаётся заданием.
- Перетаскивание файла на слот остаётся.

**Тесты.** `art.test.tsx`: одна кнопка на слот, окно с вариантами и своими путями, поиск не появляется в списке заданий; E2E `art.spec.ts` (варианты, файл с сервера, удаление с подтверждением), `walkthrough.spec.ts`; release-pass `art-variants`, `art-slot-menu` (переименовать состояние в `art-choose`), скриншоты обоих режимов.

## PR 4. Находки обхода флешки, ядро (`m5/walkthrough-core`, IMP-1, META-2, I18N; `m5-walkthrough-findings.md` пп. 1, 2, 3, 6, 10)

**Сейчас.** `crates/yaoplm-core/src/import.rs` выбирает `CD/` или `DVD/` по размеру образа (`CD_MAX_BYTES`), и маленькая DVD-игра ложится в `CD/` (пп. 1, 6); причины пропуска несут `\\?\` и английские сообщения библиотек (п. 3; `display_path` в `yaoplm-api` есть, но не везде); оценка «осталось» в начале записи считается по первым маленьким файлам (п. 2; `formatEta` в `JobsPage.tsx`, `rate` из `jobs.rs`); после конвертации в ZSO вердикт дампа теряется (п. 10).

**Нужно.**
- Тип диска: сначала prior art (правило 6: OPL Manager, OPL PC Tools, ulmake, hdl-dump — как они решают), затем порядок источников: DAT Redump (`.cue`/`.bin` — CD, `.iso` — DVD), база названий, игра с тем же ID уже на носителе, и только потом размер. В плане виден источник («DVD — по базе Redump»); переопределение CD/DVD в плане остаётся.
- Причины: `display_path` во всех фразах с путём; для частых причин (архив не докачан, повреждён, зашифрован, не образ) — свои фразы `reasons.*` с технической подробностью параметром (ADR-0029).
- Оценка «осталось»: не показывать, пока не записано достаточно (по байтам или времени), сглаживать скорость, файлы считать отдельно от байтов.
- Вердикт и хеши переносить при конвертации, когда данные образа те же (ISO ↔ ZSO), или пересчитывать по ходу сжатия.

**Тесты.** Rust: `import` — маленький образ с ID DVD-игры из DAT ложится в `DVD/`, с тем же ID на носителе — туда же, без данных — по размеру; фразы причин — тест i18n на параметры; оценка — тест на функцию сглаживания; конвертация — вердикт сохранён. E2E: `verify.spec.ts` (добавление с проверкой), `library.spec.ts`. На консоль: ничего (тип диска влияет на папку, формат файлов прежний), но строку в `docs/testing/README.md` всё равно добавить.
