# META-3: сведения об игре (план от 2026-10-27)

Решение владельца продукта 2026-10-27: сведения об игре — жанр, разработчик, издатель, дата выхода, число игроков и краткое описание — на странице игры и в плане добавления, с записью тех же полей в CFG, откуда их показывает страница сведений темы OPL. Исследование источников — `docs/research/23-game-info-sources.md`; решения — ADR-0050 (все девять рекомендаций research/23 §8 приняты).

## Что уже известно (research/23)

- OPL читает `Title`, `Genre`, `Release`, `Developer`, `Description` (плюс `#Size`, который считает сам); значения не разбирает, режет на 255 байтах, `CfgVersion` не знает, `Players` во встроенной теме не показывает (нет текстур). RiptOPL показывает `Title`, `Developer`, `Description` и слот `Players`; wOPL читает ещё `Publisher`. Чужие ключи OPL сохраняет. Русский текст виден только с русским шрифтом языкового пака.
- Tom-Bruise/VTSTech и XML GDX-X — текст ScreenScraper (CC BY-NC-SA 4.0): только корпус и сверка. В сборку идут факты из DAT libretro `metadat/developer/Sony - PlayStation 2.dat` (CC BY-SA 4.0, 4 729 игр по серийнику) и снимок Wikidata (CC0, сопоставление по названию); описания — первый абзац Википедии (CC BY-SA 4.0) по запросу через sitelink.
- Ключи и форматы менеджеров: `Players=players/N` + `PlayersText=N`, `Release=MM-DD-YYYY`, `Description` ≤255 с обрезкой по концу предложения, `Publisher`.
- Точки опоры в коде: `yaoplm-core::titles` (встроенная таблица, `include_bytes!`, ADR-0024); `yaoplm-core::settings::plan_settings` и `SettingsEdit` (план CFG по правилам CFG-2, `KeyChange` «было → станет», отказ для libconfig); `yaoplm-core::plan::CfgChange` и `GameInfo` (что показывает план); `yaoplm-core::import` (`known_title`, переключатель «Названия из базы»); `yaoplm-net::{Http, Cache, RedumpStore}` (User-Agent, `YAOPLM_OFFLINE`, кэш, загрузка по кнопке); `yaoplm-api` (`Game.known_title`, `ReadCfg`/`WriteCfg`, `PlanImport`, задания); `apps/cli` (`info`, `cfg`, `add`); `web/src/features/game/GamePage.tsx` (карточка «Сведения») и `features/add/AddGamesPage.tsx` (переключатели).

## Шаги

Каждый шаг — отдельный PR с ветки `m6/meta-3-<тема>` от `main`, вливается по порядку. Правила для каждого: сначала падающий тест, потом правка, тот же тест зелёный; `cargo fmt`, clippy, `cargo test --workspace`, `bash scripts/check-core-deps.sh`, `cargo test -p yaoplm-api --features ts-export`; `pnpm -C web lint/typecheck/test`; e2e по затронутым спекам дважды (`art.spec.ts` первым, если задета страница игры); для PR с интерфейсом — release-pass на четырёх прогонах (en/ru × светлая/тёмная × простой/расширенный) при превью `yaoplm-server-fixture`, скриншоты в `pr-assets` (`release-0.3.0/pr-<тема>/`); описание PR с таблицей «тест → на main → сейчас»; строка в `docs/testing/README.md`. Ничего не пишется на носитель без плана и подтверждения (правило 1); фразы ADR-0029 и ключи i18n `en`/`ru` в том же коммите; тексты для пользователя (`docs/I18N.md`).

1. **Данные** (`m6/meta-3-data`). `scripts/build-game-info.py` по образцу `build-data.py`: входы по пути или URL — DAT libretro и выгрузка Wikidata (скрипт сам делает SPARQL-запросы по записям с `P400=Q10680` и кладёт JSON рядом для офлайн-сборки); выход `data/game-info.json.gz` (gzip с нулевым mtime, детерминированный) с записью на серийник: факты libretro (`developer`, `publisher`, `released` как `YYYY-MM-DD`, `players`, `genre` кодом словаря), запись Wikidata (`qid`, метод сопоставления, метки `en`/`ru`, жанры кодами, разработчик, издатель, первая дата с точностью, `enwiki`/`ruwiki`), источник у каждого значения; словарь жанров — таблица в скрипте (фразы libretro и жанры Wikidata → код) и ключи `genre.<код>` в каталогах `en`/`ru`. `data/attribution.json` → `data/ATTRIBUTION.md`: DAT libretro, PSXDataCenter и скрипт robloach, Wikidata, Википедия. Ядро: `yaoplm-core::game_info` с `known_info(startup)` (встроенный файл, `OnceLock`, оба написания ID) и `yaoplm info <образ>` печатает факты. Тесты: детерминированность сборки на фикстурах входов, поиск по `SLUS_200.62` и `SLUS-20062`, код жанра без метки — ошибка теста i18n, неизвестная фраза libretro — ошибка скрипта. ROADMAP: подпункт.
2. **Ядро и CLI: запись в CFG** (`m6/meta-3-cfg`). `plan_game_info(fs, game, fields, profile, now)` в ядре поверх `plan_settings` и `SettingsEdit::set`: ключи `Title`, `Genre`, `Release` (`MM-DD-YYYY`), `Developer`, `Publisher`, `Players` + `PlayersText`, по выбору `Description` (обрезка по концу предложения в пределах 255 байт на границе UTF-8) + `DescriptionSource`; чужие ключи и порядок сохраняются, `CfgVersion` не трогается, у каждого перезаписываемого значения `CfgChange` «было → станет», libconfig — отказ фразой, резервная копия по CFG-5. Переименование обновляет `Title` в существующем CFG тем же планом (находка 7 обхода 2026-10-24). API: `Game.info` (факты сборки и что уже в CFG), `PlanGameInfo { root, game, fields, description_lang }`. CLI: `yaoplm cfg <root> <игра> --info` и `--write-info [--fields …] [--description en|ru]`. Тесты: падающий тест на «переименование не меняет `Title`», затем зелёный; корпус Tom-Bruise/GDX-X — запись не трогает ни одного чужого ключа и байта вне своих ключей; описание 300 байт режется на точке; кириллица не рвётся посреди символа; wOPL — отказ.
3. **План добавления** (`m6/meta-3-add`). `PlanImport` получает `write_info` (по умолчанию включено, как «Названия из базы»): для игр с фактами в сборке план добавляет транзакцию CFG с ключами шага 2 (без описания; сеть не опрашивается). CLI `yaoplm add --no-info`. Интерфейс: переключатель «Сведения об игре в CFG» рядом с «Названия из базы», запоминается; в плане — те же строки «ключ: станет». Тесты: `crates/yaoplm-api/tests/plans.rs` (с переключателем и без), `AddGamesPage.test.tsx`, e2e по спеку добавления дважды.
4. **Сетевые источники** (`m6/meta-3-net`). `yaoplm-net::wikidata` (поиск по названию `wbsearchentities` + `Special:EntityData`, фильтр `P400=Q10680`, метки `en`/`ru`) и `yaoplm-net::wikipedia` (`/api/rest_v1/page/summary/<статья>` для `en` и `ru` по sitelink), оба через `Http` (User-Agent, `YAOPLM_OFFLINE`, запросы по одному, `Retry-After`) и `Cache` (ETag, отрицательные ответы). API: задание `FetchGameInfo { root, game }` → факты Wikidata и описание с URL и лицензией; CLI `yaoplm cfg … --fetch-info`. Тесты только на `test_server` с фикстурами ответов; живая сеть — `YAOPLM_LIVE=1 cargo test -p yaoplm-net --test live -- --ignored`, руками. Запись описания в CFG — через план шага 2 с `DescriptionSource` и пометкой о сокращении.
5. **Страница игры** (`m6/meta-3-ui`). Карточка «Сведения»: жанр, разработчик, издатель, дата выхода (по локали), игроки, описание (целиком, с источником и ссылкой, «CC BY-SA 4.0»); одна кнопка «Записать в CFG…» → диалог плана с «было → станет» и выбором языка описания с подсказкой про шрифт; «Найти описание» — сетевое действие пользователя. Простой режим: те же факты и та же кнопка без ключей и источников. Release-pass четырёх прогонов, axe, скриншоты en/ru × светлая/тёмная. Страница пользователя в README: откуда сведения, почему описание может быть сокращено, про русский шрифт OPL.
6. **Консоль** (в `docs/testing/README.md`, серия позже): страница сведений темы OPL 1.2 beta и 1.1.0 с записанными ключами; RiptOPL с `Players`; русское описание с русским языковым паком и без него; wOPL не тронут.

## Решения владельца (2026-10-27, ADR-0050)

1. Факты libretro (разработчик, издатель, дата, игроки, жанр) — в сборку под CC BY-SA 4.0; описания из DAT не берутся.
2. Wikidata — снимок при сборке с записанным методом сопоставления плюс живой запрос по действию.
3. Описание — первый абзац Википедии по sitelink, `en` и `ru`, показ целиком со ссылкой; в CFG только по явному выбору, с обрезкой по концу предложения и `DescriptionSource`; по умолчанию английский.
4. XML GDX-X не используется (без лицензии, текст ScreenScraper); при желании — issue с просьбой о лицензии.
5. Tom-Bruise/VTSTech — только корпус и сверка.
6. План пишет `Title`, `Genre`, `Release`, `Developer`, `Publisher`, `Players` + `PlayersText`, по выбору `Description` + `DescriptionSource`; `CfgVersion` не трогается; правила CFG-2.
7. Языки: в приложении по языку интерфейса; в CFG английский, русский по выбору с подсказкой про шрифт.
8. Словарь жанров — один короткий список с метками `en`/`ru`, одни слова на карточке, в плане, в CLI и в CFG.
9. План добавления пишет сведения из сборки по переключателю; сетевые источники — только со страницы игры.

## Чего не делаем

- Сетевых запросов при добавлении и сканировании; поиска статьи Википедии по названию.
- Копирования текста ScreenScraper (Tom-Bruise, VTSTech, GDX-X) и описаний PSXDataCenter в сборку или в CFG.
- Переписывания CFG целиком (как PS2FASTLOADER) и правки файлов wOPL.
- Записи `Rating`, `Vmode`, `Aspect`, `Scan`, `Parental`: это картинки темы и CFG-2, не META-3.
