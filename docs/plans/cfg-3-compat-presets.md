# CFG-3: пресеты совместимости (план от 2026-10-27)

Решение владельца продукта 2026-10-27: пресеты совместимости — отдельная задача v0.3 (M6), и до реализации нужно явно сделать три вещи: собрать источники пресетов, согласовать их между собой и сверить с исходниками OPL разных версий и форков (правило 6), а потом описать всё это в документации — для разработчика (ADR) и для пользователя (страница о режимах). Исследование источников — `docs/research/21-compat-presets-sources.md`; решения — ADR-0049.

## Что уже известно (research/21)

- У OPL с 0.9.3 есть свой механизм пресетов: «Download Defaults» у игры и «Update game compatibility» в настройках сети тянут фрагмент CFG по паре «ID игры + устройство» с сервера OPL-CL (`sx.sytes.net/oplcl`), сливают его в `CFG/<ID>.cfg` и ставят `$ConfigSource=2`. Сервер жив (проверено 2026-10-27), записи 2015 года, лаунчеры в списке — до OPL 1.0.0, лицензии и выгрузки нет. RiptOPL и wOPL этот механизм убрали.
- Биты 1–6 одинаковы в OPL 1.1.0 и 1.2; биты 0x40/0x80 трижды меняли смысл («High Module Storage» и «Hide DEV9» до 2018/2019, потом не используются, в RiptOPL и wOPL 0x40 — «fix game buffer overrun», в RiptOPL 0x80 — «Slow Reads»). Старые пресеты со значением 100 (0x64) нельзя писать как есть.
- У RiptOPL есть встроенная таблица умолчаний из двух игр с ссылкой на issue у каждой записи; биты OPL он переводит в цифры Neutrino `-gc`, и перевод не взаимно однозначный.
- Машиночитаемых данных мало и они привязаны к устройству: GDX-X — 70 CFG только для HDD без лицензии; VTSTech/Tom-Bruise — биты у 145 игр из 13 620 без устройства и без источника; список ps2homebrew — 98 игр, таблица отчётов с колонкой «required modes» в свободном виде, MIT. Источники расходятся не в значениях, а в покрытии.
- Ни один PC-менеджер пресеты не ставит: OPL Manager правит режимы руками, PFS BatchKit копирует CFG из GDX-X целиком.

## Шаги

Каждый шаг — отдельный PR с тестами по обычной рутине; ничего не пишется на носитель без плана и подтверждения (правило 1).

1. **Дособрать источники** (без кода). Через Chrome владельца: ветка psx-place «OPL game compatibility lists», таблица Algol (вкладки по устройствам), ConsoleMods; в самой программе OPL Manager — есть ли у неё загрузка пресетов. Прочитать `script/ProcessData.sh` списка ps2homebrew и его 31 открытый issue/PR; issue OPL #1686, #1762, #984 как образец записи со свидетельством. Дописать research/21 §3.
2. **ADR** — сделано, ADR-0049: формат записи пресета (ID, класс устройства HDD/SMB/BDM, семейство загрузчика и ядро, биты в нумерации OPL, источник со строкой или issue, сборка и дата отчёта, заметка); правила согласования (несколько записей на игру показываем, не усредняем; биты 0x40/0x80 из старых данных отбрасываем; профиль RiptOPL — по его таблице перевода; загрузчику на Neutrino биты OPL не пишем); что ставить в `$ConfigSource` (1 — обновление OPL файл не тронет, 2 — заменит); использовать ли OPL-CL (вопрос 1 ниже); лицензии и `data/ATTRIBUTION.md`.
3. **Данные**: `scripts/build-compat.py` → `data/compat.json.gz` из списка ps2homebrew (MIT), CFG Tom-Bruise (GPL-3) и вручную внесённых записей со свидетельствами; GDX-X — только для сверки. Тесты на известные игры: `SLUS_217.23` → 32 на HDD и ничего на USB, `SLES_511.14` → 1, запись со значением 100 → биты 0x40 отброшены.
4. **Ядро**: `suggest_compat(startup, device, profile)` возвращает предложения с источником; применение — план CFG по правилам CFG-2 с резервной копией (CFG-5), только после подтверждения. Профиль RiptOPL получает перевод битов; у Neutrino-загрузчиков предложений нет.
5. **Интерфейс и CLI**: на карточке игры блок «Рекомендуемые режимы» с источником, устройством и сборкой отчёта и кнопкой применить; в плане добавления — подсказка, что для игры есть рекомендация; массовое «Применить рекомендации» для библиотеки → один план. CLI: `yaoplm cfg <root> <game> --suggest` и `--apply-suggested`. Тексты — для пользователя (I18N.md), одинаковые на карточке, в плане и в CLI.
6. **Документация для пользователя**: страница о шести режимах, откуда берутся рекомендации, почему рекомендация может не подойти (устройство, сборка), как её снять (в RiptOPL — явный `$Compatibility=0`, в OPL — удалить ключ). Ссылка из README.
7. **Консоль** (в `docs/testing/README.md`, серия позже): 2–3 игры с известными режимами на USB и по SMB; одна из них с рекомендацией, которая на этом устройстве не нужна.

## Решения владельца (2026-10-27, ADR-0049)

1. Только открытые источники; OPL-CL не используется ни запросом по одной игре, ни выгрузкой.
2. Применённый пресет получает `$ConfigSource=1`: это настройки пользователя, обновление из OPL их не перезапишет.
3. В простом режиме — одна строка «Для этой игры есть рекомендуемые настройки» с кнопкой применить; подробности в расширенном.
4. В v0.3 — только карточка игры и CLI; массовое применение — следующим шагом.

## Чего не делаем

- Автоматической записи пресетов при добавлении игры или сканировании.
- Скрейпинга списка OPL-CL и копирования данных без лицензии (GDX-X) в сборку.
- Копирования кода OPL и форков (AFL): только факты и логика (ADR-0002).
