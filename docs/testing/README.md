# Проверки на консоли

Здесь собрано всё, что ещё не проверено на настоящей PS2. Пока консоли нет, пункты копятся: их проверяем потом серией сессий (договорённость с владельцем продукта 2026-10-26). Каждый PR с чек-листом для консоли кладёт его файлом в эту папку и добавляет строку в таблицу ниже; пройденный чек-лист переезжает в раздел «Пройдено».

## Как пройдёт проверка

1. Владелец подключает к ПК носители по одному: флешки, SD-карту для MX4SIO, позже SD эмулятора карты памяти. Агент узнаёт носитель по серийному номеру тома (`. scripts/testdata.ps1` печатает тома), а не по букве, и сначала описывает его раскладку только на чтение (TESTING.md, «Сессии с устройствами владельца»).
2. Агент готовит носитель под пункты чек-листа: ставит нужную сборку OPL (1.1.0, 1.2.0 beta, YAOPL) через планы YAOPLM, добавляет игры и картинки. Тестовые образы — homebrew из `$YAOPLM_TESTDATA\out\` или собранные `make_boot_iso`. Образы своих дисков владелец снимает сам или просит агента записать на носитель уже снятый образ; коммерческие образы агент не скачивает (ADR-0007).
3. Ожидаемый результат каждого пункта записан в чек-листе до проверки. Если подготовка что-то меняет (другая сборка, другая флешка), агент уточняет ожидание до того, как носитель уйдёт к консоли.
4. Владелец переносит носитель на консоль и проверяет. Агент записывает фактический результат рядом с ожидаемым: отметка `- [x]` у пункта и раздел «Результат <дата>» в конце файла (сборка OPL и откуда она запущена, носитель и его серийный номер, что увидели). Расхождение — замечание; его чиним отдельным PR со своим тестом (CLAUDE.md, правило проверки исправлений).
5. После серии носитель возвращается в рабочее состояние, агент описывает, что на нём осталось.

Буквы дисков в старых чек-листах (E:, F:) — какими они были, когда чек-лист писали. Сейчас носитель узнаём по серийному номеру; тестовая флешка с 2026-10-26 — `3C76-1797` (TESTING.md, «Оборудование пользователя»).

## На консоль проверять нечего

PR, которые меняют только интерфейс: на носитель ничего не пишется, OPL разницы не увидит.

- `m5/ui-emulator-folded` (план `plans/m5-ui-polish.md`, п. 1): панель «SD эмулятора карты памяти» на карточке носителя свёрнута по умолчанию, в сводке число загрузочных карт по вариантам.
- `m5/ui-main-button` (план `plans/m5-ui-polish.md`, п. 2): тёмная «Открыть библиотеку» — у открытого носителя; шаг («Создать папки OPL», «Установить OPL…») — главная кнопка своей карточки.
- `m5/ui-menu-width` (план `plans/m5-ui-polish.md`, п. 3): выпадающие меню по ширине самого длинного пункта; пункты «Переустановить OPL…», «Сменить OPL…» больше не переносятся.
- `m5/ui-separators` (план `plans/m5-ui-polish.md`, п. 4): факты в строке через « · » на карточке носителя и в шапке библиотеки; причина подключения и версии OPL в обоих режимах за значком ⓘ.
- `m5/desktop-chrome` (план `plans/m5-ui-small-prs.md`, PR 1): в настольном приложении правый клик не открывает меню WebView2 нигде, кроме полей ввода; текст интерфейса не выделяется, выделяются только пути, ID, названия, строки для лаунчера, ошибки, журнал задания, ключи CFG и серийный номер. В браузере без изменений.
- `m5/walkthrough-core` (план `plans/m5-ui-small-prs.md`, PR 4): тип диска при добавлении — по признакам образа, затем по базе Redump, затем по игре с тем же ID на носителе, и только потом по размеру, с причиной в плане; причины пропуска архивов без `\?\` и своими словами; оценка «осталось» появляется после разгона и считается по окну; вердикт дампа переживает конвертацию ISO ↔ ZSO ↔ `ul`. Формат файлов на носителе прежний: OPL разницы не увидит.

## Что нужно от владельца

- PS2 с картой FreeMcBoot; эмулятор карты памяти; адаптер MX4SIO с SD-картой.
- Флешки FAT32 и exFAT от 8 ГБ (одну можно переформатировать между проверками).
- Образы своих дисков (CD, DVD до 4 ГиБ, игра больше 4 ГиБ) — в `$YAOPLM_TESTDATA\iso\` (TESTING.md, «Что нужно от пользователя»).
- Сеть на ПК: YAOPLM скачивает сборки OPL с GitHub.

Не на консоли, но тоже ждёт: сценарий U1 в настольном приложении на Windows (ROADMAP, M3).
