# M6: свои версии YAOPL — проверка на консоли

PR `m6/yaopl-versions` (ADR-0051). YAOPLM узнаёт версии `v2.0.0-nightly.N-<коммит>-yaopl`, `v2.0.0-rcN-yaopl` и `v2.0.0-yaopl`. Проверять сборкой YAOPLM с этим PR после того, как форк сольёт `release/versioning` и опубликует `latest` с новой версией.

Носитель: тестовая флешка `3C76-1797` (FAT32), FreeMcBoot. До проверки на ней YAOPL старой нумерации (`v1.2.0-Beta-…-yaopl`), например из PR #47.

- [ ] 1. Карточка носителя в YAOPLM до обновления: «YAOPL», версия `v1.2.0-Beta-…-yaopl`, профиль 1.2.0 beta; предлагается обновление до `v2.0.0-nightly.N-…-yaopl`.
- [ ] 2. «Обновить» по плану: заменяются только ELF и языковой пакет, старый ELF уходит в резервную копию. На PS2: OPL запускается, в «О программе» `Open PS2 Loader v2.0.0-nightly.N-<коммит>-yaopl`, игры на месте.
- [ ] 3. Карточка после обновления: «YAOPL», та же версия, что в «О программе», обновлений нет; профиль 1.2.0 beta (ZSO и exFAT разрешены).
- [ ] 4. Расширенный режим, «Другая версия…»: в списке `latest` (по умолчанию) и, когда форк их опубликует, релизы `yaopl-v…` и кандидаты (с пометкой pre-release); ни одного тега upstream (`v1.1.0` и т. п.).
- [ ] 5. «Вернуть прежнюю сборку»: на флешке снова `v1.2.0-Beta-…-yaopl`, на PS2 запускается, карточка снова предлагает обновление.
- [ ] 6. A/B-сборка `…-yaopl-nosio2man` из пакета VARIANTS, поставленная из своего файла: карточка — «YAOPL», версия с `-nosio2man`, обновление не предлагается (сравнивать не с чем).
