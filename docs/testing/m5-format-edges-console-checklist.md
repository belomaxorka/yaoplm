# M5: значение BOOT2 ровно в 64 символа (IMP-2)

Что проверяем: YAOPLM предсказывает ID игры так же, как OPL, в редком случае, когда значение `BOOT2` занимает весь 64-байтный буфер OPL (и остаётся без завершающего нуля), а `;` стоит внутри него. В OPL 1.2.0 beta такая игра с пустым ID скрыта (`GetStartupExecName`, `src/supportbase.c`). В OPL 1.1.0 правила старые: игра видна с ID `;1111111111`. YAOPLM пока применяет правила 1.2.0 ко всем профилям — это и подтверждает п. 2 (research/08 §2). PR #49.

## Что нужно

- Тестовая флешка `3C76-1797`. Оба диска уже лежат в `CD/` рядом с 16 тестовыми играми; `CD/games.bin` нет, OPL просмотрит папку заново. Копии — в `$YAOPLM_TESTDATA\out\m5-format-edges\`.
  - `Full CNF shown.iso` — wLaunchELF, `BOOT2 = cdrom0:\YAOP_000.07;` и единицы до 64 символов. Имя без ID в начале, поэтому OPL читает `SYSTEM.CNF`.
  - `Full CNF empty ID hidden.iso` — то же с `BOOT2 = cdrom0:;` и единицами до 64 символов.
- OPL 1.2.0 beta или YAOPL (с карты памяти или резервная копия YAOPL рядом с `UPDT/OPL.ELF`) и OPL 1.1.0 (сейчас в `UPDT/OPL.ELF` на флешке).

## Шаги

- [ ] 1. **OPL 1.2.0 beta или YAOPL.**
   - «Full CNF shown» есть в списке USB, в сведениях об игре ID `YAOP_000.07`, игра запускает wLaunchELF.
   - «Full CNF empty ID hidden» в списке **нет**.
- [ ] 2. **OPL 1.1.0.**
   - «Full CNF shown» есть в списке с ID `YAOP_000.07`.
   - «Full CNF empty ID hidden» **есть** в списке, с ID `;1111111111`. Не запускайте её: файла с таким именем на диске нет, игра не загрузится.
- [ ] 3. **После проверки.** Удалите оба диска из `CD/` (или оставьте: YAOPLM их не трогает) и `CD/games.bin`, если OPL его создал.

На ПК (уже проверено агентом 2026-10-26): `yaoplm scan` из `main` до PR #49 показывал второй диск игрой с пустым ID, после PR #49 — в разделе «Not listed by OPL».
