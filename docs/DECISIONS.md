# Журнал решений (ADR)

Формат: контекст → решение → последствия. Новые решения добавляются в конец. Отменённое решение не удаляется, а помечается `Заменено ADR-XXXX`.

## ADR-0001 — Стек: Tauri 2 + ядро на Rust + React/TS
*2026-10-22, принято.*
- **Контекст.** Нужны Windows, Linux и macOS, один код ядра для GUI, CLI и сервера, быстрая работа с многогигабайтными образами (research/04).
- **Решение.** Tauri 2.12 + Cargo workspace + axum + clap + React 19/TS/Vite.
  - Только в Rust есть поддерживаемые библиотеки без C-зависимостей для CHD, чтения и записи ISO, 7z, SMB2/3 и LZ4.
  - Сборки маленькие, есть официальный CI (`tauri-action`) и updater.
- **Отвергнуто.**
  - Wails v3 (Go): всё ещё beta, нет CHD, SMB-библиотека устарела. Пересмотреть после выхода v3.0.
  - Electron: инсталлятор 120–200 МБ, слабые нативные библиотеки.
  - Avalonia, Flutter, Qt: веб-интерфейс для сервера пришлось бы делать отдельно.
- **Последствия.** Высокий порог входа в Rust. Ядро держим синхронным, линтеры строгие, тестов много.

## ADR-0002 — Лицензия GPL-3.0-or-later
*2026-10-22, принято.*
- **Контекст.**
  - Хотим встроить базу названий, сделанную из PCSX2 GameIndex (GPL-3.0).
  - Родственные проекты (OrbitPS2, OPL PC Tools, PyOPLM) под GPL-3.
  - hdl-dump и pfsshell под GPL-2.
- **Решение.** GPL-3.0-or-later.
- **Последствия.**
  - Код GPL-3-проектов можно заимствовать с сохранением авторства.
  - Код OPL (AFL-3.0) и ps2sdk (AFL-2.0) используем как справочник по форматам; копирование кода нужно проверять отдельно.
  - GPL-2-only инструменты допустимо запускать только как отдельные процессы.

## ADR-0003 — Синхронное ядро, асинхронность только на краях
*2026-10-22, принято.* Крейты `core`, `formats`, `hash` и `device` не зависят от tokio, tauri и axum, что проверяется в CI. Так проще писать, тестировать и ревьюить код.

## ADR-0004 — Целевой загрузчик по умолчанию: OPL 1.2.0 beta
*2026-10-22, принято.*
- Последний stable OPL — v1.1.0 (2021). Пользователи в основном сидят на rolling-сборке 1.2.0 beta: exFAT, ZSO, PNG-only обложки.
- Профиль по умолчанию — 1.2.0 beta. Профили 1.1.0 и RiptOPL меняют правила (SPEC §4).

## ADR-0005 — Обложки всегда в PNG
*2026-10-22, принято.* OPL 1.2 beta читает только PNG (коммит c5a12a0), а 1.1.0 читает PNG, JPG и BMP. Значит, PNG подходит обоим. Размер ≤1024 px.

## ADR-0006 — Формат имени по умолчанию: `ID.Title.iso`
*2026-10-22, принято.* Если имя в старом формате (`SLUS_200.62.Title.iso`), OPL берёт ID из имени и не монтирует образ при сканировании: это быстрее и совместимо с 1.1.0. Формат `Title.iso` остаётся как опция.

## ADR-0007 — Политика источников данных
*2026-10-22, принято.*
- Приватный сервер обложек OPL Manager не используем: у него нет публичного API и условий использования.
- Изображения в сборку не включаем.
- Встраиваем только данные с совместимой лицензией (GameIndex — GPL-3.0, libretro-database — CC BY-SA 4.0) и указываем авторство.
- Источники без лицензии (xlenore/ps2-covers, compat-листы) используем только во время работы, по запросу пользователя, с кэшем.

## ADR-0008 — В v1 не форматируем диски
*2026-10-22, заменено ADR-0013.* Ошибка форматирования уничтожает данные, а повышение прав в каждой ОС устроено по-своему. Вместо форматирования даём советы по ФС. Сырой доступ к диску (HDD, позже) — только через отдельный процесс-помощник с повышенными правами.

## ADR-0009 — Server mode закрыт по умолчанию
*2026-10-22, принято.* По умолчанию сервер слушает 127.0.0.1. Для LAN нужны явный `--bind` и токен; доступ только к корням из allow-list.

## ADR-0011 — Репозиторий сначала приватный
*2026-10-22, принято.* Репозиторий `belomaxorka/yaoplm` создан приватным. Публикация — в M7 или раньше, по решению пользователя. Минусы приватного режима: минуты GitHub Actions ограничены (Windows и macOS-раннеры расходуют их быстрее), а SignPath требует публичного проекта. Если минут не хватает, macOS-сборку в CI запускаем только на тегах.

## ADR-0012 — Защита API сервера
*2026-10-22, принято.* Уточняет ADR-0009.
- **Контекст.** Сервер на 127.0.0.1 без токена доступен любому сайту, открытому в браузере пользователя. Простой кросс-сайтовый POST (форма или `text/plain`) уходит без CORS-preflight, а DNS rebinding позволяет ещё и читать ответы. Начиная с M2, через API можно будет менять и удалять файлы.
- **Решение.** Для `/api/*`:
  - `POST /api/rpc` принимает только `Content-Type: application/json`. Кросс-сайтовый запрос с таким типом требует preflight, а мы его не обслуживаем.
  - Если пришёл заголовок `Origin`, он должен совпадать с `Host`.
  - Сервер на loopback **без токена** принимает только loopback-`Host` (`localhost`, `127.x.x.x`, `[::1]`). С токеном эта проверка не нужна: токен через DNS rebinding не подделать. Поэтому за reverse proxy сервер может слушать 127.0.0.1.
  - Токен передаётся в `Authorization: Bearer`. Только для WebSocket `/api/events` допускается `?token=`, потому что браузер не умеет слать заголовки при handshake.
  - UI получает токен один раз через адрес `/?token=…`: сохраняет его в localStorage и убирает из адресной строки.
  - Токен сравнивается за постоянное время.
- **Последствия.**
  - Reverse proxy должен передавать исходный `Host` (Caddy делает это по умолчанию, в nginx нужно `proxy_set_header Host $host`). Иначе `Origin` не совпадёт с `Host`.
  - Доступа к API с другого origin нет. Если понадобится, добавим явный allow-list.

## ADR-0013 — Форматирование съёмных носителей с защитой от ошибки
*2026-10-22, принято по запросу владельца продукта. Заменяет ADR-0008.*
- **Контекст.** Пользователю нужна подготовка носителя с нуля: флешка или SD-карта для MX4SIO и эмулятора карты памяти. Неправильная ФС, разметка или размер кластера — частая причина того, что OPL не видит игры или тормозит. Риски из ADR-0008 никуда не делись: ошибка уничтожает данные, а повышение прав в каждой ОС своё.
- **Решение.** Форматирование входит в продукт (SPEC DEV-3, DEV-4) с такими ограничениями:
  - Только съёмные диски на USB или SD-шине. Системный и загрузочный диск, а также диски с примонтированной ОС, недоступны вообще.
  - Перед планом показываем модель, серийный номер, размер, текущие разделы и метки томов.
  - Подтверждение вводом (например, метки или размера диска), а не одной кнопкой.
  - Прямо перед записью диск проверяется ещё раз по тому же идентификатору: если он сменился или переподключился, операция отменяется.
  - Запись выполняет отдельный процесс-помощник с повышенными правами (`yaoplm helper --stdio`), а не основной процесс.
  - Параметры (ФС, MBR/GPT, кластер, выравнивание) берутся из профиля носителя и загрузчика, пользователь может их изменить.
  - В автотестах форматируем только файлы-образы, никогда реальные диски.
- **Последствия.** Появляется самая опасная операция в продукте, поэтому её код отдельно ревьюит владелец и проверяет на своих носителях. Этап — v0.2: до этого остаётся диагностика носителя только на чтение (DEV-2).
- **Уточнение по research/06 (2026-10-22).**
  - Доступ к диску: повышенные права нужны только на Windows (помощник через UAC и защищённый именованный канал). На Linux непривилегированный помощник получает дескриптор устройства через udisks2 (один запрос polkit), на macOS — через `authopen` (нужен прототип). В режиме сервера и в Docker форматирования нет.
  - Подтверждение вводом — размер диска.
  - Сначала пишем файловую систему, таблицу разделов — последней; идентичность диска проверяем через тот же дескриптор, которым пишем.
  - Только диски с логическим сектором 512 байт: FatFs в OPL собран с `FF_MAX_SS 512` (проверено в `fjtrujy/FatFs` ветка `iop-r0.16`).
  - Выбор движка (свой exFAT или системный на Windows и macOS) зависит от вопроса о патентах exFAT — SPEC, открытый вопрос 6.

## ADR-0014 — Установка загрузчиков только с официальных релизов
*2026-10-22, принято.* Дополняет ADR-0007.
- **Контекст.** Владелец хочет ставить из программы разные сборки: официальный OPL, RiptOPL, форк с MMCE и другие (SPEC LDR-1…5). Бинарники PS2-программ меняются часто, у них разные лицензии.
- **Решение.**
  - Скачиваем только с официальных релизов проектов (GitHub Releases и аналоги), по явному действию пользователя. В сборку YAOPLM бинарники загрузчиков не входят.
  - Фиксируем сборку по SHA-256 ассета, а не по тегу: «плавающие» теги вроде `latest` перезаписываются на месте. Хеш берём из GitHub API, если релиз его публикует, иначе считаем и показываем свой. Кэшируем, показываем лицензию и ссылку на исходники.
  - Конфиги способов запуска (FreeMcBoot, PS2BBL) не пишем, а показываем пользователю строки для них (SPEC BOOT-1).
  - Можно установить из своего архива без сети.
  - Эксплойты (FreeMcBoot, PS2BBL) на физическую карту памяти не ставим.
- **Последствия.** Каталог загрузчиков — данные, которые обновляются без выпуска новой версии программы. Когда меняется формат релизов какого-то проекта, достаточно поправить его запись в каталоге.

## ADR-0015 — Эталонные проекты как источник граничных случаев
*2026-10-22, принято.*
- **Контекст.** В исходниках OPL, его форков и соседних программ годами копились исправления для особых случаев, ошибок железа и прошивок. Многие из них нигде не описаны, кроме комментариев в коде, коммитов и issues. Искать их по форумам долго.
- **Решение.**
  - Ведём справочник репозиториев `docs/research/REFERENCES.md` и их локальные клоны в `D:\yaoplm-testdata\refs\<owner>__<repo>`.
  - Перед реализацией формата или работы с устройством читаем соответствующий код в официальном OPL и форках, их коммиты и issues; при необходимости — ветки форумов (psx-place читаем через Chrome пользователя).
  - Сравниваем реализации. Эталон поведения — официальный OPL (CLAUDE.md: «Follow OPL source»); форки и другие менеджеры — источник граничных случаев и исправлений, которые проверяем, прежде чем переносить. В комментарии к нашему коду указываем файл и коммит источника.
  - Лицензии: код OPL (AFL-3.0) и ps2sdk (AFL-2.0) не копируем, а переписываем по смыслу (ADR-0002). Код под GPL-3-совместимыми лицензиями можно переносить с указанием авторства.
- **Последствия.** Справочник нужно поддерживать в актуальном состоянии (`git pull` по клонам), а находки — записывать в research/.
