Привет! Продолжаем разработку YAOPLM. Веха M2 закрыта (PR #7, тег `v0.0.3`). В ядре есть:
- импорт ISO/ZSO/BIN/CUE с нарезкой `ul` на FAT32;
- переименование, удаление и перенос CD↔DVD;
- журнал с откатом и докатом;
- задания с прогрессом;
- CLI.

Начинаем **M3 — Десктопный интерфейс (MVP)**.

1. Прочитай документы:
   - `CLAUDE.md`;
   - `docs/SPEC.md`: LIB-4, LIB-5, UI-1…UI-3, IMP-9, IMP-10, GAME-1…GAME-3;
   - `docs/ARCHITECTURE.md`: §4 слой API, §5 модель заданий;
   - `docs/ROADMAP.md`: веха M3;
   - `docs/DECISIONS.md`, особенно ADR-0009, 0012, 0020 и 0021;
   - `docs/TESTING.md`: раздел про проверку интерфейса агентом.

   Справочники: `docs/research/01-competitors.md`, `05-oplnova-audit.md`, `09-import-prior-art.md`, `REFERENCES.md`.
2. Сначала разберись, что уже есть:
   - `web/`: React 19, TS 6, shadcn/ui `radix-nova`, Tailwind 4, TanStack Query и Virtual, React Router 7, react-i18next;
   - транспорты в `web/src/api/transport.ts`;
   - типы в `web/src/api/generated/`: их генерирует ts-rs, руками не правим;
   - запросы в `crates/yaoplm-api/src/protocol.rs`:
     - `ListDevices`, `InspectDevice`;
     - `ScanLibrary` (это задание);
     - `PlanImport`, `RenameGame`, `DeleteGame`, `MoveGame`, `PlanInit`, `PlanRecovery` возвращают `PlanView`;
     - `ExecutePlan`, для удалений нужен `confirmDelete`;
     - `GetJob`, `ListJobs`, `CancelJob`;
     - события `JobEvent`.

   Попробуй CLI (`yaoplm devices`, `device`, `add`, `rename`, `rm`, `mv`, `recover`) на временной папке: GUI должен повторять это поведение.
3. Перед каждым экраном посмотри, как это сделано у соседей в `D:\yaoplm-testdata\refs\` (сначала `git pull`):
   - OrbitPS2 Manager: `angular/src/app/shared/services/jobs.service.ts` и `jobs-panel` (последовательная очередь, живой журнал шагов, одно пересканирование после очереди), экран библиотеки, диалоги обложек;
   - opl-linux-toolbox (форк Orbit);
   - POUM (Tauri 2 + React, наш стек);
   - OPL-PC-Tools (Qt), PS2IsoManager (WPF);
   - OPLNova и его баги из research/05: клик по игре стирает CFG, Delete удаляет ISO без подтверждения.

   Бери лучшие идеи и не повторяй чужих ошибок. Что взято и откуда — коротко запиши в `docs/research/`.
4. Работай в ветке `m3/desktop-ui` маленькими коммитами с ID требований. Задачи:
   - **Выбор устройства.** Список из `ListDevices` с вердиктом диагностики (`InspectDevice`); ошибки (NTFS на USB, exFAT для OPL 1.1.0, системный диск) видны сразу; оттуда переход к библиотеке.
   - **Библиотека (LIB-5).**
     - Сетка и список, поиск, фильтры (CD/DVD, ISO/ZSO/UL, с предупреждениями), сортировка.
     - Виртуализация на 3000+ играх через TanStack Virtual.
     - `ScanLibrary` как задание с прогрессом.
     - Обложек пока нет (M4): нужна аккуратная заглушка.
   - **Карточка игры (LIB-4).**
     - ID, носитель, формат, размер, пути, части `ul`, CFG, VMC, читы.
     - Предупреждения с переводом по `code`.
     - Действия: переименовать, перенести CD↔DVD, удалить (GAME-1…GAME-3), всегда через экран плана.
   - **Добавление игр.**
     - Десктоп: диалоги выбора файлов и папок, drag-and-drop путей (плагин tauri dialog; проверь версию и лицензию).
     - Сервер: просмотр папок только внутри разрешённых корней. Нужен новый запрос API, например `ListDir`, с проверкой `PathPolicy` и тестами.
     - Название и CD/DVD можно переопределить для каждой игры.
     - Перенос вместо копирования — только явным переключателем.
   - **Экран плана.**
     - Транзакции, шаги, объёмы, свободное место, предупреждения и блокеры.
     - Удаления файлов пользователя подсвечены и требуют отдельного подтверждения (`confirmDelete`).
     - Пропущенные источники видны вместе с причинами.
   - **Панель заданий.**
     - Прогресс, скорость, оставшееся время, текущая игра, отмена.
     - Итоги по транзакциям: готово, откачено, не начато, прервано.
     - По идеям Orbit: живой журнал шагов (если нужен новый `JobEvent`, добавь его в API с тестами), одно пересканирование библиотеки после очереди записи, «Очистить завершённые».
   - **Незавершённая операция.** Если на носителе есть журнал, перед любыми изменениями показываем баннер с `PlanRecovery`: откат или докат.
   - **Настройки (UI-1…UI-3).** Профиль загрузчика, стиль имён (`ID.Title` или `Title`), язык, тема. Полная навигация с клавиатуры.
   - **Общие правила.** Все строки через i18n, `en` и `ru`. TS-типы — только из `generated/`. Новые запросы — с ts-rs и тестами в `yaoplm-api`.
   - **e2e на Playwright** против `yaoplm-server` с фикстурной библиотекой из `yaoplm-test-support`:
     - сценарий: открыть устройство → увидеть игры → добавить игру → план → подтвердить → прогресс → игра в списке;
     - переименование и удаление с подтверждением;
     - скриншоты в PR: светлая и тёмная тема, `en` и `ru`, ширина 1280 и 800 px.
