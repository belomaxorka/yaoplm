## Что делаем: второй PR вехи

По плану вехи (ROADMAP, KICKOFF прошлой версии) второй PR — это обложки при импорте и слоты типов картинок (ART-8, ART-2, ART-5), редактор CFG (CFG-2) и VMC (VMC-1), плюс решение владельца от 2026-10-23: проверка дампов при добавлении. Это много. **Предложи владельцу разбить его на два PR** и делай по очереди:

**PR 2a — добавление игр и картинки:**
1. **Обложки при импорте (ART-8, SPEC §5.4.1, ADR-0025 с уточнением).** Галочка «Скачать обложки» на экране добавления, включена по умолчанию, запоминается. После «Показать план» запускается то же задание `FetchArt` с охватом «только недостающие» по ID образов из плана (журнал по играм прямо под планом, отмена). Когда поиск закончился, план импорта перестраивается: за транзакцией копирования каждой игры идёт транзакция записи `ART/<ID>_COV.png` из кэша. Одно подтверждение, одно задание. API: `PlanImport` получает ссылку на готовый план поиска (`covers: <id плана>`), ядро принимает список `ArtItem` и само добавляет транзакции; CLI — `yaoplm add --covers`. Дубликаты ID получают одну обложку. Ненайденная обложка попадает в «пропущено» и никогда не блокирует импорт; без сети импорт работает как сейчас.
2. **Проверка дампов при добавлении (GAME-5, пункт ROADMAP M5).** Хеши считаются в том же проходе, что и запись на носитель (поток копирования идёт ещё и в хешер `yaoplm-hash`), без отдельного чтения флешки. После записи вердикт по DAT Redump сразу, а хеши кладутся в кэш по ключу нового файла на носителе (том + путь + размер + mtime, как в `crates/yaoplm-api/src/verify.rs`: `keys`, `put_hashes`, `attach_checks`). Без DAT хеши всё равно сохраняются. Переключатель «Проверять дампы при добавлении» в настройках и на экране добавления, по умолчанию включён; флаг у `yaoplm add`. **Для CD из BIN/CUE и CHD сверять сырую дорожку данных** (2352 байта на сектор), как её хеширует Redump: только так CD-игра может получить «подтверждён» (ISO с CD не совпадает никогда, ADR-0026). Сжатие в ZSO при добавлении — хешировать данные ISO до сжатия.
3. **Слоты типов картинок (ART-2, ART-3).** В карточке игры вместо одной обложки — ряд слотов: `COV`, `ICO`, `COV2`, `BG`, `SCR`, `SCR2`, `LGO`, `LAB`; у каждого превью, размер и «Скачать», «Заменить» (файл, буфер, перетаскивание), «Удалить»; каждое действие — тот же план с резервной копией. Размеры типов — research/02 §7 (COV 140×200, COV2 242×344, LAB 18×240, ICO 64×64, LGO 300×125, SCR/SCR2 250×188, BG 640×480; RiptOPL — двойные COV/ICO). Источники по типам: xlenore — `COV`; libretro-thumbnails — `Named_Snaps` → `SCR`, `Named_Titles` → `SCR2`, `Named_Logos` → `LGO`. Новые типы — новые `ArtKind` в том же конвейере (ADR-0025). Массовая загрузка получает выбор типов.
4. **Импорт арт-паков (ART-5).** Zip-бэкапы OPL Manager с archive.org (пользователь скачивает сам), папки, `art.tar` → `ART/<ID>_<SUFFIX>.png` с перекодированием, план с подтверждением и резервной копией заменяемых файлов. Никогда не обращаться к частному серверу OPL Manager (правило 3).

**PR 2b — настройки игры:**
5. **Редактор CFG (CFG-2).** Режимы совместимости (биты 0x01–0x20; 0x40/0x80 только в профиле RiptOPL), DMA (только HDD), GSM, слоты VMC, читы вкл/выкл, PADEMU, AltStartup. Ключи и значения — research/02 §6.3; OPL удаляет ключ, когда значение возвращается к умолчанию. Сохранять неизвестные ключи и их порядок (правило 2), резервная копия перед каждым изменением (CFG-5, `.yaoplm/backup/`), запись через план. Парсер с сохранением неизвестных ключей уже есть: `crates/yaoplm-formats/src/cfg.rs`.
6. **Создание VMC (VMC-1).** Правильно отформатированная карта 8/16/32/64 МиБ (не пустой файл) и назначение в слот (`$VMC_0`/`$VMC_1`). Формат — research/02 §9 (как `genvmc`: без ECC, страницы 512 байт, кластер 1024 байта, IFC с кластера 8, FAT, корень с `.` и `..`, заливка 0xFF, точный размер). Файл на BDM должен быть непрерывным: предвыделение (ADR-0019). Проверка — `vmc::opl_check` в `crates/yaoplm-formats/src/vmc.rs`. Источники: `Adubbz/mymcplusplus` (`ps2mc.py`, функция `format()`, GPL-3, можно портировать с атрибуцией), `bucanero/ps2vmc-tool` (GPL-3); `modules/vmc/genvmc/genvmc.c` в OPL — AFL, только логика, код не копировать. **Находка:** Orbit (`src/services/vmc.service.ts`) создаёт файл из нулей и пишет, что OPL отформатирует его при первом запуске. По `sysCheckVMC` (`src/system.c` OPL) это не так: без сигнатуры, `mc_type == 2` и совпадения размера OPL ставит размер 0 и карту не использует.

Каждый PR — со своим чек-листом для консоли в `docs/testing/` и скриншотами.

## Правила, которые появились недавно (важно)

- **Тексты ядра — фразы (ADR-0029, docs/I18N.md, правила 6–8).** Тип `Phrase` из крейта `yaoplm-i18n` (реэкспорт в `yaoplm-core`): `Phrase::title`, `Phrase::error`, `Phrase::notice`, `Phrase::reason` и `.with("name", value)`, `.count(n)`. Уведомление: `Notice::warning(Phrase::notice("noSpace").with("needed", n).with("free", f))`; план и транзакция: `Plan::titled`, `Transaction::titled`. Английский текст ядро рендерит из `web/src/locales/en/translation.json`, поэтому новый ключ добавляется в `en` и `ru` в том же коммите, иначе падают тесты. Разделы каталога: `titles`, `errors` (целые предложения), `notices` (уведомления, предупреждения, советы, причины пропуска; код — последняя часть ключа), `reasons` (фрагменты после двоеточия, со строчной). Числа передаются числами (`count` выбирает форму множественного числа, размеры — `{{size, bytes}}`), технические подробности (сообщения ОС, позиции ошибок разбора) — текстом внутрь переведённого предложения.
- **Проверки локализации** (`web/tests/unit/i18n.test.ts`): ключи и формы множественного числа во всех языках, плейсхолдеры, типографика, перевод каждой фразы из исходников Rust, **совпадение параметров каждой фразы с плейсхолдерами шаблона** (с файлом и строкой при расхождении), отсутствие неиспользуемых ключей. В Rust плейсхолдер без значения — ошибка в отладочной сборке.
- **Интерфейс**: `phraseText`, `errorText` (`web/src/lib/phrase.ts`), `useNoticeText` (`web/src/lib/notices.ts`); у типов API есть `phrase`, `titlePhrase`, `errorPhrase`; числа форматируются по языку («5,0 ГиБ»). Строки только по-английски в ключах, глоссарий и типографика — docs/I18N.md.
- Владелец хочет, чтобы в русском интерфейсе не было английского и дублей текста, а после больших изменений — **углублённую проверку**: статические проверки, исчерпывающие тесты, ручной просмотр в браузере на обоих языках, независимое ревью диффа отдельным агентом.
