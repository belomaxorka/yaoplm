# YAOPLM — локализация интерфейса

Правила для каждого PR, который меняет интерфейс. Языки: `en`, `ru` (список — `web/src/i18n/index.ts`). Каталоги строк: `web/src/locales/<язык>/translation.json`.

## Обязательно

1. Любая строка, которую видит пользователь, идёт через i18next (`t(...)`). Функция приходит **в том же коммите** со строками на всех языках; «переведу потом» не бывает.
2. Ключи — по-английски, camelCase, по разделам экрана или функции: `dump.*`, `convert.*`, `jobs.*`. Код уведомления ядра показывается через `notices.<code>`; значения перечислений API — через ключ с префиксом (`plan.steps.<op>`, `dump.status.<status>` и т. д.).
3. Множественное число — суффиксы i18next: `en` — `_one`, `_other`; `ru` — `_one`, `_few`, `_many`, `_other`. Если фразу можно построить без согласования с числом («Подтверждено: {{count}}»), строим так: тогда ключ без суффиксов во всех языках. Формы с одинаковым текстом — признак того, что суффиксы не нужны.
4. Плейсхолдеры `{{name}}` одинаковые во всех языках. `count` может не входить в текст формы `_one` только в `en`: в `ru` форма `_one` покрывает и 21, 31…, поэтому число в ней нужно.
5. Типографика: в `ru` — «ёлочки», в `en` — “лапки” и ’ (не прямые `"` и `'`); многоточие «…», а не три точки; тире «—» с пробелами в `ru`; ни двойных пробелов, ни пробелов перед знаками препинания. Безличные формы, а не первое лицо: «Сканирование библиотеки…», а не «Сканирую…».
6. Тексты ядра для пользователя — фразы (ADR-0029): ключ каталога и параметры, `Phrase::title("…")` (раздел `titles`) или `Phrase::error("…")` (раздел `errors`). Английский текст ядро берёт из каталога `en`, поэтому новый ключ добавляется во все языки в том же коммите. Числа передаются числами: `count` выбирает форму множественного числа, размер пишется `{{size, bytes}}`.
7. Уведомления пока устроены иначе: код (`notices.<code>`) и английское сообщение ядра, которое интерфейс показывает подробностью, если в нём есть что-то кроме подписи (имена, размеры). Новый код уведомления в ядре = новый ключ `notices.<code>` во всех языках.

## Автопроверки

`web/tests/unit/i18n.test.ts`, входит в `pnpm -C web test` и в CI:

- одинаковые ключи во всех языках;
- все формы множественного числа, которые нужны языку (`Intl.PluralRules`), и только у ключей с формами;
- одинаковые плейсхолдеры;
- дубли ключей в самом JSON (`JSON.parse` молча оставляет последний);
- пустые строки, пробелы по краям, двойные пробелы, `...`, прямые кавычки и апострофы, пробел перед знаком препинания;
- русская строка, совпадающая с английской и содержащая английские слова;
- перевод для каждого кода уведомления из исходников ядра (`Notice::info/warning/error`, `skip(..)`, `fn code()` в `model.rs` и `advice.rs`);
- перевод для каждой фразы ядра и API (`Phrase::title/error/notice`), и ни одного ключа `titles.*`/`errors.*`, которого ядро не использует;
- перевод для каждого значения перечислений, которые интерфейс превращает в ключ (таблица в тесте: `StepOp` → `plan.steps`, `VerifyStatus` → `dump.status` и др.). Новое такое перечисление добавляется в таблицу.

## Ручная проверка перед PR

- Прочитать новые строки в обоих языках на экране (скриншоты en и ru в PR).
- Сверить термины с глоссарием.
- Формулировки — короткие и конкретные: что произошло и что делать; без канцелярита.

## Известные пробелы

- Подробности уведомлений, предупреждений игр, советов по носителю и причин пропуска приходят из ядра по-английски (переводится только подпись). Следующий шаг — перевести их на фразы, как заголовки и ошибки (ADR-0029).
- Строки журнала проверки дампов и поиска обложек с ошибками — английские.
- Размеры в русском интерфейсе пишутся с точкой («5.0 ГиБ»), а нужна запятая: форматировать числа через `Intl.NumberFormat` по языку.
- Тексты ошибок ОС и сетевой библиотеки показываются как есть (Windows отдаёт их на языке системы). CLI пока только на английском.
